## 一、做得对、不要改动的地方

**① 采集段选择了「纯 DOM 读取」，而没有拦截 API。** AGENTS.md 里把它写成了硬性约束：「收集只做被动 DOM 读取和点击页面已有按钮，**不构造、不重放数据源的接口请求**」。我上一轮建议过拦截 XHR，但你这一版对共享账号更保守，也更安全。**不要改成拦截 API。**

**② 顺手做了「按 Semrush 平台标签筛博客来源」。** `onScrapedRows` 里只保留带「博客」标签的行。这等于在采集环节就先做了一层类型过滤，比后面靠规则猜页面类型更准。

**③ 明确放弃全自动。** 文档里写的是「有意不做全自动直接发布」。这个取舍是对的，理由是规避内容质量风险。

**④ 工程严谨度超出预期。** 70 个单测、`config.js` 集中放「待联调项」、MV3 的断点续跑、AI 请求超时主动中止、评论正文用 `{{LINK:锚文本}}` 占位符，再由后台替换成 `<a>`。这些细节说明它不是一次生成的空壳。

## 二、两处必须立刻修改的冲突

### ① 同一页面会留下两条链接

这是最要紧的一处，涉及两个函数：

- `generateComment()` **无条件**要求模型输出 `{{LINK:...}}`，两次都没有就直接 `throw`；
- `publisher.js` 的 `fill()` 里：`if (form.linkMethod !== 'comment_body') { put(pick(form.url || '#url'), identity.website, 'website') }`

这两处合起来的结果是：**在 `website_field` 和 `author_link` 这两类站点上，正文里会被塞进一个 `<a>`，同时还没漏掉去填网址字段或留下昵称链接。** 也就是一页两条指向同一个站的链接。

原帖讲「不同网站留链接的方式不同」，重点就在**只走一条**。一页两条同样锚点指向同一域名，是垃圾外链最典型的信号之一。群里那位说博客评论外链「一半左右被标 spam」的，很可能就碰到这个问题。

改法：`generateComment` 里把 `linkMethod` 作为入参传进去；当它是 `website_field` 或 `author_link` 时，**不许正文出现链接**，把「必须带占位符」这条硬性要求的适用范围收窄到 `comment_body` / `markdown` 两类。那两类的 stdout 报错逻辑也相应放宽——**「无链接就抛错」这个设计本身是错的**，无链接但有 website 字段照样是有效外链。

### ② 锚文本策略和结论相反

`generateComment` 的提示词原文：

> 「基于我的主关键词「${mainKeyword}」做变体——可加相关前缀/后缀、同义词或长尾组合（例如 “best X”、“X for beginners”、“cheap X alternatives”），**不要每次都用一模一样的裸关键词**」

咱们前面确认过的是**反过来**的：优先裸 URL 或品牌名，**绝不用精准匹配关键词做锚文本**。`best X` / `cheap X alternatives` 这种商业型锚文本批量出现在无关博客的评论区，是所有反垃圾模型最先命中的特征。

改法：把提示词换成「锚文本只能是网站品牌名或裸 URL，禁止使用带商业修饰词的关键词短语」。用户想多样化的话，多样化的是**评论文案**，不是锚文本。

## 三、方案里缺的三块（按优先级）

**① SPAM 清洗——整条链路只缺这一个环节。** 全库没有 spam 相关字段，唯一的筛选是 `minAscore: 25`（页面 AS ≥ 25）。AS 是 Semrush 自家的权重分，和「Ahrefs 判不判它 spam」是两回事——群里 12 群那位黄牛明确说过「我找外链的时候**限制了 AS 分数的**，找出来还是这样」。

接法（不依赖未知 API，稳妥版）：资源库导出 CSV → 域名整批贴进站内[外链 Spam 查询](https://seo.web.cafe/spam/)（单次上限 1 万，可导 CSV）→ 结果回填黑名单。如果那个页面有可供插件自动填入的入口，再进一步做成按钮一键弹出+回填；在没有确认之前，别按「有 API」去写。

**② 效果验证——整套系统唯一的自适应机制。** 现在发布后只有人工「备注」按钮能写一句话。缺少：T+10 分钟回访看评论是否渲染、rel 是什么；T+30 天回访看 Ahrefs 有没有收进去、有没有被标 spam。`publisher.js` 已经有 `detect` 能拿页面 DOM，加一个「回访模式」的成本很低——把当时填的选择器存下来，定时重开页面读自己的那条评论即可。

**③ 滚雪球（评论区挖站长网站）——原帖的核心玩法，代码里采了一半。** `analyzer.js` 已经把 `commentHtml` 抓下来（`commentList.innerHTML.slice(0, 60000)`），但文档功能清单里标的是「未实现」。**数据已经在手里了，只差把它解析成种子域名。** 这是投入产出比最高的一处补全。

## 补丁四：结论落库时记住表单结构（`background/publish.js`，新增，不依赖上面三条）

这是**投入产出比最高的一处**，因为它把「每个站都问一次 AI」变成「问一次就够」。在 `markPublished` 后面加：

```js
/**
* 表单指纹库：站点表单结构 → 留链通道。同一个指纹第二次遇到时跳过 AI 识别，
* 直接用缓存的选择器（WordPress 默认主题占绝大多数，重复率很高）。
* 存 chrome.storage.local 的 formIndex 键：{ [fingerprint]: { linkMethod, selectors, hits, ok, fail } }
*/
function fingerprintOf(form, pageUrl) {
const sel = [form.comment, form.author, form.email, form.url, form.submit, form.saveInfo].join('|');
const host = (() => { try { return new URL(pageUrl).hostname; } catch { return ''; } })();
return `${host}|${sel}`;
}

async function cacheForm(form, pageUrl) {
if (!form || !form.comment) return;
try {
const st = getState();
const idx = st.formIndex || {};
const fp = fingerprintOf(form, pageUrl);
const prev = idx[fp] || { hits: 0, ok: 0, fail: 0 };
idx[fp] = { linkMethod: form.linkMethod || 'website_field', selectors: form, hits: prev.hits + 1, ok: prev.ok, fail: prev.fail };
st.formIndex = idx;
await save('formIndex'); // save 是合并写入，只动这一个键
addLog('publish', `表单指纹已缓存（${idx[fp].linkMethod}，累计 ${idx[fp].hits} 次）`, 'info', pageUrl);
} catch (e) {
addLog('publish', `表单指纹缓存失败：${e.message}`, 'warn', pageUrl);
}
}
```

调用点在 `onStep` 的 `detectForm` 分支，`rt.manual = { ...m, ..., form, frameId };` 之后加一行 `await cacheForm(form, url);`。

用的时候，在 `detectForm` 分支开头（`await begin('asstDetecting');` 之前）先查缓存：

```js
const cached = (getState().formIndex || {})[fingerprintOf({}, url)];
if (cached && cached.hits >= 1) {

```

> 注意：`fingerprintOf({}, url)` 这种查法是错的——指纹里含 selector，查缓存时还不知道 selector。**改成只按 host 查**：`fingerprintOf` 拆成 `hostOf(url)` 和 `formKey(host, form)`，缓存按 host 存一个候选数组，同 host 命中第 1 条直接用。这样成本几乎为零，也避免了「同站不同文章表单略改」导致的完全 miss。

```js
export function extractCommenterDomains(commentHtml, { excludeHosts = [], selfHost = '' } = {}) {
const urls = [];
const re = /<a\b[^>]*href=["']([^"']+)["']/gi;
let m;
while ((m = re.exec(String(commentHtml || '')))) urls.push(m[1]);
const seen = new Set();
for (const u of urls) {
try {
const h = new URL(u, 'https://x.invalid').hostname.replace(/^www\./, '').toLowerCase();
if (!h || h === 'x.invalid') continue;
if (selfHost && h === selfHost) continue;
if (excludeHosts.some((e) => h === e || h.endsWith('.' + e))) continue;
if (/\/(wp-|feed|comments|category|tag)/.test(u)) continue; // 站内导航
seen.add(h);
} catch { /* 相对链接或无 host，跳过 */ }
}
return [...seen];
}
```

## 补丁三：`fill()` 一页只留一条链接（`content/publisher.js`，完整替换）

在 `setNativeValue` 函数下面加 `stripAnchors`：

```js
/** <a href="...">锚文本</a> → 锚文本（剥掉全部标签），供「有独立网址框」时使用 */
function stripAnchors(html) {
  return String(html || '')
    .replace(/<a\b[^>]*>([\s\S]*?)<\/a>/gi, (_, inner) => inner.replace(/<[^>]+>/g, '').trim())
    .replace(/<\/?[a-z][^>]*>/gi, '')
    .replace(/[ \t]{2,}/g, ' ')
    .trim();
}
```

然后把 `let lastFill = null;` 到 `fill()` 函数结束整段换成：

```js
let lastFill = null;
function fill(cfg) {
  try {
    const form = cfg.form || {};
    const identity = cfg.identity || {};
    const filled = { comment: false, author: false, email: false, website: false };

    const scopeHint = form.formSelector ? q(form.formSelector) : null;
    const scopes = [scopeHint, document].filter(Boolean);
    const pick = (sel) => {
      for (const sc of scopes) {
        const el = sel ? q(sel, sc) : null;
        if (el) return el;
      }
      return null;
    };
    const put = (el, value, key) => {
      if (!el || !value) return false;
      setNativeValue(el, value);
      filled[key] = true;
      return true;
    };

    // 一页只留一条链接：有独立网址框 → 填网址 + 正文剥掉 <a>；
    // 没有网址框（或网址为空）→ 链接才留在正文里。

    // 所以只要网址框存在，就必须走网址框。
    const urlEl = pick(form.url || '#url');
    const useUrlField = !!urlEl && !!identity.website;
    put(pick(form.comment), useUrlField ? stripAnchors(cfg.comment) : cfg.comment, 'comment');
    put(pick(form.author), identity.name, 'author');
    put(pick(form.email), identity.email, 'email');
    if (useUrlField) put(urlEl, identity.website, 'website');

    const saveEl = pick(form.saveInfo);
    if (saveEl && saveEl.type === 'checkbox' && !saveEl.checked) saveEl.click();

    const scopeEl = scopeHint || (pick(form.comment) && pick(form.comment).closest('form')) || document;
    const submitBtn = findSubmitIn(scopeEl, form.submit);
    lastFill = {
      submitSel: form.submit || '',
      formSelector: form.formSelector || '',   // 原版漏了这一项，submit() 里的 q(lastFill.formSelector) 恒为 null
      resourceUrl: cfg.resourceUrl || null,

      submitFound: !!submitBtn,
      linkChannel: useUrlField ? 'url_field' : 'comment_body',
    };
    if (!filled.comment) return { ok: false, error: '评论文本框未找到或未填入' };
```

## 补丁五：T+10 分钟回访（新文件 `background/verify.js`）

```js

import { idbGetAll, idbPut } from '../lib/idb.js';
import { addLog } from '../lib/storage.js';
import { ANALYZE_SELECTORS } from '../lib/config.js';

/** 注入到目标页执行：找自己的评论并读 rel */
function scanOwnComment(cfg) {
  try {
    const scope = (cfg.commentList || []).map((s) => document.querySelector(s)).find(Boolean) || document;
    const hit = [...scope.querySelectorAll('a[href]')]
      .find((a) => cfg.domain && (a.href || '').toLowerCase().includes(cfg.domain));
    if (!hit) {
      const pageText = (document.body?.innerText || '').toLowerCase();
      return { ok: true, found: false, moderation: /awaiting moderation|等待审核|待审核/.test(pageText) };
    }
    const box = hit.closest('li, .comment, .comment-body, article, p') || hit;
    return {
      ok: true,
      found: true,
      rel: (hit.getAttribute('rel') || '').toLowerCase(),
      anchorText: (hit.textContent || '').trim().slice(0, 60),
      snippet: (box.textContent || '').replace(/\s+/g, ' ').slice(0, 160),
    };
  } catch (e) {
    return { ok: false, error: String((e && e.message) || e) };
  }
}

function waitTabComplete(tabId, timeoutMs) {
  return new Promise((resolve) => {
    const timer = setTimeout(() => { chrome.tabs.onUpdated.removeListener(onUpd); resolve(false); }, timeoutMs);
    function onUpd(id, info) {
      if (id !== tabId || info.status !== 'complete') return;
      clearTimeout(timer);
      chrome.tabs.onUpdated.removeListener(onUpd);
      resolve(true);
    }
    chrome.tabs.onUpdated.addListener(onUpd);
  });
}

export async function runVerifyDue(now) {
  const rows = await idbGetAll('published');
  const due = rows.filter((r) => r.verifyAt && r.verifyAt <= now && r.verifyStage !== 'done');
  for (const r of due) {
    addLog('verify', `回访 ${r.url}`, 'info', r.url);
    try {
      const tab = await chrome.tabs.create({ url: r.url, active: false });
      await waitTabComplete(tab.id, 30000);
      const [{ result }] = await chrome.scripting.executeScript({
        target: { tabId: tab.id, allFrames: true },
        func: scanOwnComment,
        args: [{
          domain: (() => { try { return new URL(r.targetUrl).hostname.replace(/^www\./, ''); } catch { return ''; } })(),
          commentList: ANALYZE_SELECTORS.commentList,
        }],
      });
      await chrome.tabs.remove(tab.id);
      const res = result || {};
      // 状态机：渲染出来 → live（rel 决定传不传权重）；没渲染但有审核提示 → moderation 等 24h；
      // 没渲染也没审核提示 → dead，这个域名进黑名单
      const stage = res.found ? 'done' : (res.moderation ? 'moderation' : 'dead');
      await idbPut('published', {
        ...r,
        verifyStage: stage,
        verifiedAt: Date.now(),
        rel: res.rel || '',
        anchorText: res.anchorText || '',
        snippet: res.snippet || '',
        verifyAt: stage === 'moderation' ? now + 24 * 3600 * 1000 : r.verifyAt,
      });
      addLog('verify', res.found ? `评论已渲染（rel=${res.rel || '无，dofollow'}）`
        : (res.moderation ? '待审核' : '未渲染，判 dead'), res.found ? 'success' : 'warn', r.url);
    } catch (e) {
      await idbPut('published', { ...r, verifyStage: 'retry' });
      addLog('verify', `回访失败：${e.message}`, 'warn', r.url);
    }
    await new Promise((s) => setTimeout(s, 5000 + Math.random() * 5000));
  }
}
```

写入 `published` 时（在 `markPublished` 里）补三个字段：

| 回访结果 | 判定 | 动作 |
|---|---|---|
| 渲染出来了、`rel` 为空 | dofollow | 真正有效的外链，计入成果 |
| 渲染出来了、`rel` 含 nofollow / ugc | 不传权重 | 单列一类，**别和 dofollow 混算成功率** |
| 没渲染、页面有审核提示 | 待审核 | T+24h 再查一次 |

`onupgradeneeded` 里那段 v2 迁移不用动，它用 `objectStoreNames.contains` 判断的，v4 打开老库照样能过。解析函数放 `analyzer.js`，**纯函数、不访问网络**：

```js
/** 从评论区 HTML 提取评论者留下的外链域名——这些就是同行站长，全是已验证可发的资源 */
export function extractCommenterDomains(commentHtml, { selfHost = '', excludeHosts = [] } = {}) {
  const out = new Set();
  const re = /<a\b[^>]*href=["']([^"']+)["']/gi;
  let m;
  while ((m = re.exec(String(commentHtml || '')))) {
    try {
      const h = new URL(m[1], 'https://x.invalid').hostname.replace(/^www\./, '').toLowerCase();
      if (!h || h === 'x.invalid' || h === selfHost) continue;
      if (excludeHosts.some((e) => h === e || h.endsWith('.' + e))) continue;
      if (/\/(wp-|feed|comments|category|tag|author)\//.test(m[1])) continue;
      out.add(h);
    } catch { /* 相对链接，跳过 */ }
  }
  return [...out];
}
```

接进 `analysis` 阶段，每条资源分析成功后 `idbPut('seeds', { domain, fromUrl, refDomain: targetDomain, addedAt: Date.now() })`。**去重方向必须做对**：已经出现在 `backlinks` / `analysis` / 黑名单里的域名直接跳过，否则跑两轮就会在几十个站之间打转，以为在滚雪球，其实是在原地绕圈。

## 补丁七：三条硬约束落到配置（`lib/config.js`）

```js
dailyPerDomain: 1,        // 同一域名每天最多 1 条
weeklyPerDomain: 2,       // 同一域名 7 天内最多 2 条
requireIndexed: true,     // 页面未被收录则不发布
```

`requireIndexed` 别靠脚本访问 Google 查（会触发人机验证），先用人工抽查一批攒判断，共享账号 + 人工点提交的组合下这一项可以人工替代。
